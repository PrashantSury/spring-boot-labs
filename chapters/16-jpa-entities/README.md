# Chapter 16: JPA entities

By the end of this chapter Ledgerly's `Account` is a JPA entity: Hibernate creates its table, inserts and loads it, stores its type as text and its balance as exact money, and two copies of the same row compare equal.

## Why you need this

In chapter 15 every query repeated the same `id, number, owner, balance` mapping by hand. Ledgerly has 40 tables; that is a lot of copy-paste and a lot of places to forget a column. JPA maps rows to objects from annotations. It also has three classic traps that have cost real banks money: enums stored as numbers, money stored as `double`, and `equals`/`hashCode` that break once an id is generated.

## What you will learn

- **`@Entity`, `@Table`, `@Id`, `@GeneratedValue(IDENTITY)`, `@Column`:** the mapping.
- **The no-arg constructor:** JPA builds objects by reflection; make it `protected`.
- **`@Enumerated(EnumType.STRING)`:** the enum's name in the column, not its position.
- **`BigDecimal` with `precision = 19, scale = 2`:** exact money.
- **`equals`/`hashCode` for entities:** id-based equals, constant hashCode.
- **`ddl-auto`:** Hibernate can create tables for a lab; real apps use Flyway and `validate`.

## The shape of an entity

```java
@Entity
@Table(name = "accounts")
public class Account {
  @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
  @Column(nullable = false, unique = true, length = 20)  private String number;
  @Enumerated(EnumType.STRING)                           private AccountType type;
  @Column(nullable = false, precision = 19, scale = 2)   private BigDecimal balance;
  protected Account() {}          // for JPA only
}
```

**Traps**

- No `@Enumerated(STRING)`: `SAVINGS` is stored as `0`. Add `NRI` before `CURRENT` later and every current account becomes NRI.
- `double` for money: `0.10 + 0.20 = 0.30000000000000004`.
- `Objects.hash(id)` as hashCode: put a new account in a `HashSet`, persist it, and `contains` says false.
- Lombok `@Data` on an entity generates exactly that broken equals/hashCode (and a `toString` that can load lazy relations).
- Records cannot be entities: JPA needs a no-arg constructor and mutable fields.
