# Chapter 20: Entity relationships

By the end of this chapter a Ledgerly customer owns many accounts in JPA: one foreign key, mapped from both sides, kept in sync by a helper method, loaded lazily, and serialisable to JSON without an endless loop.

## Why you need this

The first version of Ledgerly's customer mapping did three bad things at once: Hibernate created a surprise `customer_accounts` join table, a new account added to `customer.getAccounts()` was saved with no owner, and `GET /customers/1` died with a `StackOverflowError` because customer → accounts → customer → ... never ended. All three come from not knowing which side of a relationship owns it.

## What you will learn

- **`@ManyToOne` + `@JoinColumn`:** the owning side; its table gets `customer_id`.
- **`@OneToMany(mappedBy = ...)`:** the inverse side; a read-only view of the same foreign key.
- **Helper methods:** `addAccount` sets both sides, because JPA only stores the owning side.
- **`FetchType.LAZY`:** the customer is loaded only when you ask for it.
- **JSON loops:** `@JsonIgnore` on the back-reference (or, better, DTOs).
- When to avoid `@OneToOne` and `@ManyToMany` (teaching section).

## The shape of it

```java
// Account (owning side)                       // Customer (inverse side)
@ManyToOne(fetch = FetchType.LAZY, optional = false)   @OneToMany(mappedBy = "customer")
@JoinColumn(name = "customer_id")                      private List<Account> accounts = new ArrayList<>();
@JsonIgnore
private Customer customer;                             public void addAccount(Account a) { accounts.add(a); a.setCustomer(this); }
```

**Traps**

- No `mappedBy`: two unrelated relationships, and a join table nobody asked for.
- Adding to the inverse list only: nothing is saved (or `customer_id` is null and the insert fails).
- `@ManyToOne` is EAGER by default; always say `LAZY`.
- `@ManyToMany` with extra data (a joint account's role, the date added) needs its own entity instead.
- Returning entities from a controller: loops, lazy proxies and `hibernateLazyInitializer` in the JSON.
